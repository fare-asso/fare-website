# AGENTS.md

Guide for AI coding agents working on the FARE Website project.

## Project Overview

A modern Astro (SSR) full-stack application for Fédération des Associations du Réseau Étudiant de Haute-Bretagne (FARE), a student federation network. Features include:

- Public website with project showcases (Bouge-ta-Prison, BagadAsso, Agorae)
- Admin dashboard for content, associations, events, and memberships
- Contact forms with CAPTCHA protection
- Email notifications and rich-text content editing

**Tech Stack:** pnpm, Astro 7 (SSR via `@astrojs/node` standalone), React 19 (islands), TypeScript, Tailwind CSS v4, Shadcn/ui, Prisma 7 (`@prisma/adapter-pg`), Supabase (Auth + Storage), Nodemailer, react-email, TanStack Query/Form/Table.

**Architecture in one paragraph:** Pages and layouts are `.astro` files rendered on-demand (SSR) that read data directly from Prisma in their frontmatter. Interactive UI is shipped as React **islands** (`client:*`). Mutations and read-for-refetch go through **Astro Actions** (`src/actions/`, called via `astro:actions`). Auth is Supabase (server-side only, cookie SSR); the DB is Prisma over Postgres via a driver adapter. There is **no browser Supabase client** — all Supabase SDK/auth/DB access is server-side.

## Code Style & Conventions

### Type Safety

- **TypeScript strict mode** is enforced (`tsgo` for `.ts/.tsx`, `astro check` for `.astro`).
- All functions must have return type annotations.
- No `any` types; use `unknown` + type guards only when unavoidable.
- Runtime validation with **arktype**.
- Environment variables are validated by **arkenv** (`src/env-schema.ts` + `@arkenv/vite-plugin`); import the validated object from `@/env`.

### Imports & Exports

- **Use `export type`** for types/interfaces.
- **ES modules only**; Node builtins use the `node:` protocol (`import fs from "node:fs"`).
- Imports auto-sorted by oxfmt; oxlint enforces type-only imports/exports.
- Path aliases: `@/` → `src/`, `#public/` → `public/` (tsconfig + `astro.config.ts`).

### Formatting & Linting

- **oxlint** (lint) + **oxfmt** (format) are the source of truth. Config: `oxlint.config.ts`, `oxfmt.config.ts`. Linters are scoped to `.ts/.tsx`; `.astro` is covered by `astro check`.
- **80** col width, **4-space** indent, **no semicolons**, **double quotes** (incl. JSX).
- **Naming:** camelCase vars/functions, PascalCase components/types, CONSTANT_CASE constants.
- oxlint checks accessibility (a11y). Tailwind classes auto-sorted by oxfmt (`cn`, `twMerge`, `cva`).
- Custom local oxlint rules live in `tools/oxlint-rules/` (e.g. `local/no-try-catch`, `local/no-non-public-env-in-client`, `local/require-action-name-matches`).

### Component Patterns

- **`.astro` for pages/layouts**, React **islands** for interactivity, plain React (no directive) for presentational components Astro renders to zero-JS HTML.
- **Shadcn/ui:** reuse `src/components/ui/` first; install via the shadcn CLI with pnpm if needed.
- **Tailwind v4** utility-first (via `@tailwindcss/vite`); global styles in `src/styles/globals.css`.
- Every React component has a typed prop interface.

### Error Handling

- **Actions return a discriminated union:** `{ success: true; value: T } | { success: false; error: string }` (drop `value` when there is no payload). Callers narrow on `success` — never optional `success?`/`error?`.
- **Every entry-point action is wrapped with `wrapAction()`** from `@/lib/action` (see [Server Actions](#server-actions)).
- **Use `tryCatch` from `@/lib/utils` instead of `try/catch` — everywhere.** Overloaded:
    - `await tryCatch(promise)` — wrap a Promise (DB, fetch, storage…)
    - `await tryCatch(() => asyncOp())` — async thunk (also catches sync throws)
    - `tryCatch(() => syncOp())` — sync thunk (`JSON.parse`, cookie set…); returns a sync `Result`

    Same Rust-style union in every form. Narrow on `success`, call `captureActionError(result.error)` on genuine exceptions, return a French error string.

- **Plain `try/catch` is forbidden** — the only exception is inside `tryCatch` itself in `src/lib/utils.ts` (inline `oxlint-disable`). Enforced by `local/no-try-catch`; silence inline only with a documented reason.
- For pure side-effect calls where failure is intentionally ignored, use `void tryCatch(() => …)` (or just `await sendEmail(...)`, which reports its own failures).
- **Report genuine exceptions with `captureActionError(error)`** from `@/lib/sentry` on the `tryCatch` failure branch — never a bare `console.error()`. Do NOT capture validation/permission/not-found early returns (expected denials). `sendEmail` already captures internally — don't double-capture.
- Never expose sensitive data in error messages. Client-side errors surface via Sonner toasts.
- Throw only `Error` instances (oxlint `useThrowOnlyError`). Validate with `.safeParse()` (Zod) / `Schema(input) instanceof type.errors` (arktype) — never throw from validation.

## Database & Migrations

- **Schema:** edit `schema.prisma`. Prisma **7** with the **`@prisma/adapter-pg`** driver adapter — the client is built as `new PrismaClient({ adapter: new PrismaPg({...}) })` (`src/helpers/db.ts`).
- **Generated client** lives in `src/generated/prisma` (custom output, bundled into `dist`) — never edit it.
- **Never hand-edit migration files** — use the Prisma CLI.
- **Local dev:** `pnpm prisma migrate dev --name your_migration`.
- **Production:** migrations run at **build time** in the Docker builder (`prisma migrate deploy && prisma db seed`), against `SUPABASE_POSTGRES_PRISMA_DIRECT_URL`. The runtime container does **not** run migrations (no prisma CLI shipped) — it only queries via the pooled `SUPABASE_POSTGRES_PRISMA_URL`.
- `prisma db seed` (`prisma/seed.ts`) makes the codebase the source of truth for permissions (upserts the canonical set, prunes removed ones).
- Config is in `prisma.config.ts`. After schema changes run `pnpm run check:types`.
- **Roles:** only `ADMIN` is used for authorization (the `MEMBER`/`ASSO_OWNER` roles and the Espace-Asso portal were removed). Authorization is permission-based (see below).

## Security & Authentication

### Permission-Based Access Control (PBAC)

Granular permission checks, **never** role checks.

**Core principles:**

- All sensitive operations check permissions via `src/helpers/permissions.ts`.
- **Never trust client-side checks** — always validate server-side (in the action).
- Supabase Auth handles authentication; the middleware resolves the user + permissions once per dashboard request.

**Permission checking pattern (Astro Action):**

```typescript
import type { ActionAPIContext } from "astro:actions"
import { hasPermission } from "@/helpers/permissions"
import { getUserWithPermissions } from "@/helpers/supabase/astro"
import { wrapAction } from "@/lib/action"

async function someActionImpl(
    input: TSomeInput,
    context: ActionAPIContext
): Promise<{ success: true } | { success: false; error: string }> {
    const user = await getUserWithPermissions(context)
    if (!user) return { success: false, error: "Authentification requise" }
    if (!hasPermission(user, "create:article")) {
        return {
            success: false,
            error: "Vous n'avez pas la permission de créer des articles"
        }
    }
    // …proceed
    return { success: true }
}

export const someAction = wrapAction("someAction", someActionImpl)
```

**Helpers:**

- `hasPermission(user, permissionName)` — check a specific permission.
- `getUserWithPermissions(context)` — authenticated user + permissions (used inside actions).
- Dashboard **pages** read `Astro.locals.user` (populated by the middleware) — no second `getUser`.

**UI visibility** (island): hide sidebar items by permission, e.g. `hidden: !permissions?.find((p) => p.name === "access:articles")`. See `PERMISSIONS.md` for the full list + seeding.

**Schema:**

```prisma
model User { permissions UserPermission[] }
model Permission {
  name String @unique  // "create:article", "access:presse"
  title String
  category String
  description String?
}
```

### Environment Variables

⚠️ **Never commit `.env` / `.env.local`.**

- Schema: **`src/env-schema.ts`** (arktype). Validated at build **and** runtime by arkenv; import the validated `env` from **`@/env`** — do not read `process.env` directly in app code.
- **`PUBLIC_`-prefixed vars are baked into the client bundle** by Vite (`envPrefix: "PUBLIC_"`) — only use the prefix for values that must reach the browser. Everything else is server-only and read from `process.env` at runtime.
- The local `local/no-non-public-env-in-client` oxlint rule blocks non-`PUBLIC_` env use in client-capable files.
- `.env.example` documents the variables. Missing/invalid required vars fail the build (arkenv) and container start (`src/env.ts`).

### Form Security

- Public/dashboard inputs validated with Zod v4 or arktype (schema in `src/schemas/`).
- CAPTCHA (Friendly Captcha) required on public forms; verify the token server-side (`@/helpers/captcha/verify`).
- Sanitize rich-text (Tiptap) before storing.

## Architecture Patterns

### Server Actions

Actions live in `src/actions/<domain>/` and are registered in `src/actions/index.ts`. **Each action is a private `…Impl(input, context)` function wrapped by `wrapAction()`** (adds a Sentry span + evlog). The registry maps each wrapped action into `export const server = {…}`, which Astro exposes as `actions` to callers.

```typescript
// src/actions/items/createItemAction.tsx
import { type } from "arktype"
import type { ActionAPIContext } from "astro:actions"
import prisma from "@/helpers/db"
import { hasPermission } from "@/helpers/permissions"
import { getUserWithPermissions } from "@/helpers/supabase/astro"
import { wrapAction } from "@/lib/action"
import { captureActionError } from "@/lib/sentry"
import { tryCatch } from "@/lib/utils"
import { CreateItemSchema, type TCreateItem } from "@/schemas/items"

async function createItemActionImpl(
    input: TCreateItem,
    context: ActionAPIContext
): Promise<
    { success: true; value: Item } | { success: false; error: string }
> {
    // 1. Auth + permission guards (early returns — NOT captured by Sentry)
    const user = await getUserWithPermissions(context)
    if (!user) return { success: false, error: "Authentification requise" }
    if (!hasPermission(user, "create:item")) {
        return { success: false, error: "Vous n'avez pas la permission" }
    }

    // 2. Validation (early return — NOT captured)
    const data = CreateItemSchema(input)
    if (data instanceof type.errors) {
        return { success: false, error: "Un ou plusieurs champs sont invalides." }
    }

    // 3. Risky IO via tryCatch — capture on failure, return a French error
    const item = await tryCatch(prisma.item.create({ data }))
    if (!item.success) {
        captureActionError(item.error)
        return { success: false, error: "Echec de la création de l'élément" }
    }

    return { success: true, value: item.value }
}

export const createItemAction = wrapAction("createItemAction", createItemActionImpl)
```

Register it in `src/actions/index.ts`:

```typescript
import { createItemAction } from "./items/createItemAction"

export const server = {
    items: {
        // accept JSON input (the common case)
        createItemAction: jsonAction(createItemAction),
        // accept a FormData with File uploads (decodeFormPayload unwraps it)
        addItemWithImageAction: filePayloadAction(addItemWithImageAction)
    }
}
```

Call it from an island:

```typescript
import { actions } from "astro:actions"

const { data, error } = await actions.items.createItemAction(value)
if (error || !data.success) {
    toast.error(data?.error ?? "Erreur")
} else {
    await queryClient.invalidateQueries({ queryKey: ["items"] }) // refresh
}
```

**Key patterns:**

- `jsonAction(fn)` = `defineAction({ handler })` (JSON input). `filePayloadAction(fn)` = `defineAction({ accept: "form", handler })` and decodes the FormData via `decodeFormPayload` (used for File uploads — see `src/lib/formPayload.ts`).
- Auth/permission/validation failures are **early returns**, not exceptions — do not `captureActionError` them.
- Wrap every genuinely risky IO (DB, storage up/download, PDF/zip) in `tryCatch`; capture + return a French message on failure. `sendEmail` self-reports — just `await` it.
- **No `revalidatePath`.** Astro pages are live SSR. Dashboard lists refresh via **TanStack Query**: the page SSR-seeds `initialData`, the island `useQuery({ queryKey, queryFn: () => actions.x.list(), initialData })`, and mutations call `queryClient.invalidateQueries({ queryKey })`. Public pages are pure SSR (no Query). Each mutable list therefore has a matching read action.
- Actions never navigate — they return data; the caller navigates. Typed failures use `ActionError` where a specific HTTP/code is needed.
- Only entry-point actions are wrapped/registered; internal sub-routines (e.g. captcha verification) are not.

### Islands (interactive React)

- Add the directive where the component is used in `.astro`: `client:load`, `client:visible`, or `client:only="react"` (for `window`-only libs like Leaflet).
- **Keep a shared React-context / Radix-portal subtree as ONE island** (e.g. a Dialog trigger + content + TanStack form is a single hydration root) — do not split trigger and content across the Astro/React boundary.
- **`<Image>` (astro:assets) works only in `.astro`.** In islands, pass a precomputed URL / plain `<img>`. Sharp is a direct dependency so the on-demand image optimizer works at runtime.
- Cross-island state (rare) → nanostores. URL state → `src/hooks/useSearchParam.ts`.

### Pages & Data

- Page frontmatter does the SSR data reads (Prisma) and computes metadata (`<title>/<meta>`). `Astro.redirect()` / `Astro.rewrite("/404")` replace `redirect()`/`notFound()`.
- Links are `<a href>`; fonts use the Astro Fonts API (`<Font>` in the base layout).

### Form Handling

- **TanStack React Form** + Zod v4 / arktype validation, submitting to an Astro Action.
- In `onSubmit`: `const { data, error } = await actions.x(value)`; track pending with local state/`useTransition`; map `error` / `isInputError(error)` and `data.error` to the UI; success/failure via Sonner toasts.

### Email Templates

Templates live in **`emails/`** (repo root) as react-email components. `react-email` is a **runtime dependency** (email is rendered on-demand in actions).

```tsx
// emails/welcome.tsx
import { Heading, Text } from "react-email"
import BaseTemplate from "./base"

export default function WelcomeEmail({ name }: { name: string }) {
    return (
        <BaseTemplate>
            <Heading>Bienvenue</Heading>
            <Text>Bonjour {name}</Text>
        </BaseTemplate>
    )
}
```

Send with the `sendEmail` helper. It returns `{ success: true } | { success: false }` (failures caught internally + reported to Sentry). Do NOT wrap in `try/catch`.

```typescript
import { render } from "react-email"
import { sendEmail } from "@/helpers/email"

// abort-on-failure
const email = await sendEmail({
    to: "secretariat@fare-asso.fr",
    subject: `Nouvelle demande d'adhésion - ${record.association}`,
    html: await render(<EmailTemplate />)
})
if (!email.success) return { success: false, error: "Echec de l'envoi du mail" }

// best-effort — no need to check .success
await sendEmail({ to: "…", subject: "…", html: "…" })
```

## Common Gotchas & Warnings

### Astro / Islands

- ⚠️ Run `pnpm exec astro sync` if `astro:actions`/`astro:*` types resolve to `any`.
- ❌ Don't use `<Image>` or `import.meta.env.PUBLIC_*` string-building inside a `client:only` island expecting server env — client islands only get **baked `PUBLIC_`** values.
- ⚠️ Behind a TLS-terminating proxy, Astro's action origin check is disabled (`security.checkOrigin: false` in `astro.config.ts`) because the Node adapter sees `http` internally.

### Type Safety / Env

- ❌ No `any`. ⚠️ Prisma types auto-generate from `schema.prisma` (`prisma generate`).
- ⚠️ Read env via `@/env`, not `process.env`. `PUBLIC_` = client-baked; anything else is server-only/runtime.

### Database

- ❌ Never hand-edit migrations. ⚠️ Migrations run at **build**, not container start.
- ⚠️ Migrations use `..._DIRECT_URL`; runtime queries use the pooled `..._PRISMA_URL`.
- ⚠️ Check `@relation(onDelete: Cascade)` before deleting parents.

### Forms & Input

- ❌ Never skip validation. ⚠️ Sanitize Tiptap HTML. ⚠️ File uploads → Supabase Storage (validate type/size), never the DB.
- ⚠️ CAPTCHA verified server-side in the action.

### Performance / Styling

- ⚠️ Refresh dashboard data with TanStack Query `invalidateQueries` (no `revalidatePath`).
- ❌ No inline styles — Tailwind classes. Custom CSS only in `src/styles/globals.css`.

### Deployments

- ⚠️ `PUBLIC_*` must be present at **build** (baked). Server secrets are **runtime**-only (validated by `src/env.ts` at container start).

## Testing Strategy

> **Tests are REQUIRED.** Every new feature, action, form, non-trivial schema, or behavioural bug fix ships with tests in the **same PR**.

**Stack:**

- **Vitest** with two projects (config via `getViteConfig` from `astro/config`, so `astro:*` virtual modules resolve). `pnpm test` runs both.
- **MSW** mocks outbound HTTP in the node project (`onUnhandledRequest: "error"` — an unmocked request fails the run).
- **Playwright** (`@vitest/browser-playwright`) drives headless Chromium; components render via `vitest-browser-react`.

| Change | Required tests |
| --- | --- |
| New/changed action | Node test covering the full branch + IO matrix |
| New/changed schema with rules | Schema test in `src/schemas/__tests__/` (if non-trivial) |
| New/changed form component | Browser test |
| New/changed helper with logic | Node unit test in `__tests__/` |
| Behavioural bug fix | Regression test that fails without the fix |

**Projects:** `node` (`environment: "node"`, msw, schema/action/helper tests — `pnpm run test:node`) and `browser` (islands via `vitest-browser-react` — `pnpm run test:browser`).

**Conventions:**

1. Tests live in a `__tests__/` subfolder of the source dir (never siblings; source never moves). Node tests: `.test.ts(x)`; component tests: `.browser.test.tsx`.
2. Reuse `src/test/mocks.ts` (hoistable mocks for db, supabase astro client, email, sentry…) and `src/test/factories/<domain>.ts`. `src/test/browser.tsx` `renderWithClient` wraps islands in a `QueryClientProvider`.
3. **Action tests** import the `wrapAction`-wrapped export (the shared sentry/evlog mocks make it a passthrough), call it with **input only** (the context arg is optional in tests), and cover: invalid payload, each auth/permission denial, every IO failure branch, partial-failure cleanup, best-effort continuation, and the happy path with the exact payload.
4. **Component tests** mock the form's `astro:actions` module and the captcha module; the action mock returns `{ data, error }` (Astro's shape), asserting render, client validation (action NOT called), valid submit payload, and success/error UI.
5. Test env vars are defined in `vitest.config.ts` (`testEnv`, applied to both projects); the browser project also stubs `process.env` in `vitest.browser.setup.ts`.

Also rely on `pnpm run check:types`, `pnpm run check:lint`, and manual `pnpm run dev`.

## CI/CD Pipeline

**On every push/PR (`.github/workflows/checks.yaml`):**

1. `quality` job (with a dummy `env:` block so arkenv validation passes): `prisma generate` → `astro sync` → `check:lint` → `check:types` → `check:format` → `knip`.
2. `test` job: `test:node`, then install Playwright Chromium and `test:browser`.

Both must be green to merge.

**Dependency updates:** Taze, Mondays 09:00 UTC → PR to `@finxol`.

**Deployment (Docker, multi-stage):**

- Builder: `pnpm install --frozen-lockfile` → `prisma generate` → `prisma migrate deploy && prisma db seed && astro build` → `pnpm prune --prod`.
- `PUBLIC_*` are build `ARG`s (baked). Non-baked server vars get **mock `="build"` values** in the builder so arkenv validation passes; real values are injected at **runtime**. Only `SUPABASE_POSTGRES_PRISMA_DIRECT_URL` (migrate/seed) and `SENTRY_AUTH_TOKEN` (sourcemaps) are real build secrets (BuildKit secret mounts).
- Runner copies the **prod-only** `node_modules`, `dist`, `public`, `package.json` and runs `node ./dist/server/entry.mjs`.
